## 合議結果：主戦場切替および次Unit優先順位について

### 1. 判断
**主戦場方針は「A3（段階的移行）」が妥当です。**
PM仮決定案に**全面的に賛成**します。

### 2. 理由
*   **思想の維持**: 「Roleを関数として扱う」というAI事業OSの重要思想を、コンテキスト汚染から守るため。
*   **物理的限界の回避**: APIチャットアプリの添付容量やリポジトリ参照能力の限界に対し、実利的な逃げ道が必要なため。
*   **検証の継続**: 全てをVSCodeに移すと、開発中のFlow Runtime自体のドッグフーディング機会が失われるため。

### 3. VSCode移行ゲートの条件（A3採用時）
以下のいずれかに該当する場合を移行条件とすべきです。
*   **物理制約**: 添付ファイルがAPIチャットの容量上限を超える、またはコンテキストウィンドウを圧迫する場合。
*   **参照深度**: 影響調査や実装において、3ファイル以上の相互依存関係の把握が必要な場合。
*   **動的環境要求**: 実機でのビルド、テスト、ランタイムエラーのトレースが必要なRole（Infra, Debugger等）である場合。

### 4. 次Unit候補の優先順位
1.  **候補1：Handoff Runtime / Migration Gate**
    *   理由：方針A3を実現するための必須インフラであるため。
2.  **候補3：Output Schema Validation**
    *   理由：VSCode側（外部）で生成された成果物がFlowの整合性を壊さないための防波堤が必要なため。
3.  **候補2：Runtime Log / Trace**
4.  **候補4：Review Gate Extension**

### 5. VSCode側の運用制約（コンテキスト汚染防止）
*   **1 Role / 1 New Chat**: 過去の作業ログが残ったチャットを使い回さない。
*   **Explicit Scope**: PMがHandoffで指定したファイル以外の読み込みを禁止する。
*   **Mandatory Artifact Return**: VSCodeでの成果物は必ずAPIチャット側のArtifactとして再登録し、そこでの承認を最終正とする。

### 6. リスクと推奨アクション
*   **リスク**: APIチャットとVSCodeの間で「Humanによる手動コピペ」がボトルネックとなり、開発体験が損なわれる。
*   **推奨アクション**: **U-FLOW-13**において、VSCode側で読み込ませるための「コンテキスト最小化済みのプロンプト一式（Packet）」をワンクリックでエクスポートできる機能を最優先で実装してください。
